# Wave 4 A11y Audit — 2026-05-23

## Method

Static source-code audit over the 4 core UI flows (Login, Feed/AnnotateLayout, AnnotateDoc, Admin). `@axe-core/playwright` was not present in `frontend/node_modules`, so no automated browser scan was run. Every interactive component was read directly. Checks performed: button/link accessible names, keyboard reachability (no `<div onClick>` without role/tabindex), WCAG 2.1 AA color contrast (Tailwind token → HSL → relative-luminance calculation), skip-links, form label association, modal ARIA (`role="dialog"` + `aria-modal` + `aria-labelledby`), `aria-live` on dynamic regions, `<html lang>`, and heading hierarchy. Two serious findings were fixed inline as part of this audit.

## Verdict

The codebase is close to public-deploy readiness on accessibility. The two most impactful issues (missing `aria-labelledby` on raw-div dialogs in MirrorHealthPage and RetentionPage) were fixed as part of this audit. The one remaining serious gap is the lack of focus-trap and Escape-key handling on those same two raw-div modals — screen-reader and keyboard users can open the dialogs but cannot be contained within them and cannot dismiss via Escape. This is an admin-only surface with low traffic, which reduces severity, but the fix (migrating to the existing Radix `Dialog` primitive) is low effort and recommended before Phase 6 launch. The moderate findings (color-only status signals in MirrorHealthPage, missing inner-pane landmarks on AnnotateLayout, aside aria-hidden on Login) are hygiene items that do not block deployment but should be addressed in Phase 6. No axe-core automated run was performed; a browser-based scan is recommended once the app is running in CI.
